PII redaction SDK for LLM traces

Traces flowing into the observability platform could carry customer PII. Best-effort masking was the convenient answer; I chose the strict one.

Built the SDK across five languages on Microsoft Presidio (NER plus regex recognizers), with defense in depth across four stages — client SDK, OpenTelemetry collector, server-side ingestion, and retroactive ClickHouse cleanup — and fail-closed semantics so an unmasked span is dropped rather than stored.

Decomposition Razorpay · 2025

Account Statements out of the monolith

Bank account statements lived inside a PHP monolith that everything else depended on. Pulling them out meant moving 37 million records without merchants noticing.

Led the migration into a Go microservice: a phased migration worker with S3 ingestion and CSV fallback instead of temp tables and a downtime window, then a full cutover of statement-fetch traffic and read/write database segregation so reads never again contend with writes. The service now handles 12–20 lakh statements a day across RBL, Yes Bank, IDFC, and Axis.

Go · MySQL · Kafka (MSK) · S3 · Kubernetes · Airflow

Search & onboarding Razorpay · 2025

Elasticsearch-backed statement search

Statement search took around fifteen seconds and leaned on MySQL. The obvious fix — write to Elasticsearch synchronously in the request path — would have set worker CPU on fire.

Did the load analysis first (1,480 requests a minute, 840 peak goroutines), then designed an asynchronous upsert pipeline and hybrid keyword-plus-fuzzy retrieval, and got architectural sign-off before rollout. The shared Elasticsearch infrastructure is now reused across multiple pods. Onboarded IDFC and Yes Bank onto the platform along the way, including statement-fetch workers and Airflow DAGs.

How I work

Three habits behind the numbers.

Start from the question

Curiosity is the engine.

"Why can't we see what our LLMs cost?" became the observability platform. "Why does search take fifteen seconds?" became a load analysis and a new architecture. I follow the question across service boundaries and call that ownership, not scope creep.

Own the outcome

Spec to on-call.

I write the tech spec, build it, roll it out, and carry the pager. When something outside my service breaks a merchant, I take the call and drive the root cause — the pager not being mine has never been a reason to wait.

Prove it in production

Correctness over shortcuts.

Phased migrations over downtime windows, fail-closed over best-effort, 95% test coverage nobody asked for. If a system can't be observed and tested, I don't consider it shipped.
